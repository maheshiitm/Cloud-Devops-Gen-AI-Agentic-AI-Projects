# Migration Assessment

## Source Environment

The source workload is assumed to be hosted on VMware infrastructure.

Assessment areas:

- CPU utilization
- Memory utilization
- Disk utilization
- Network throughput
- Application dependencies
- Database dependencies
- Operating system
- Security controls
- Backup requirements
- Availability requirements
- RTO
- RPO

## Assessment Process

1. Discover servers.
2. Identify applications.
3. Map dependencies.
4. Capture performance baselines.
5. Identify licensing requirements.
6. Classify workloads.
7. Identify migration blockers.
8. Estimate AWS sizing.
9. Define migration waves.
10. Obtain application-owner approval.

## Migration Strategy

Recommended strategy:

- Rehost where appropriate.
- Replatform where beneficial.
- Refactor only where business value justifies additional effort.

## Exit Criteria

The workload can proceed to migration when:

- Dependencies are documented.
- Target architecture is approved.
- Security requirements are approved.
- AWS capacity is available.
- Rollback plan is approved.
- Application owner approves the migration window.
